## 1. 全体構成

```
[PC ブラウザ（会社側 /app）]  [スマホ（ドライバー側 /d）]
            │ HTTPS（httpOnly Cookie セッション）
            ▼
[Next.js 16（App Router / Server Actions / Route Handlers）]
  ├ src/server/*      業務ロジック（権限判定・検証・トランザクション・監査ログ）
  ├ src/adapters/*    差し替え可能な外部接続
  │   ├ bank:     demo / csv / （将来）正式API
  │   ├ email:    console（送信せず記録）/ smtp / resend
  │   ├ storage:  local / supabase（非公開バケット）
  │   ├ llm:      none（ルール文） / anthropic
  │   ├ esign:    none（将来の電子署名）
  │   └ cleanup:  csv / （将来）API
  └ 定期処理 /api/cron（リマインド送信・再試行・銀行同期・アクションカード更新）
        │
  [PostgreSQL]   [非公開ファイル保存]
```

各外部接続は画面上部と「設定 > 外部接続」に **未接続 / デモ / 実接続** を表示する。

## 2. 利用者と権限

| 権限 | できること |
|---|---|
| 経営者・会社管理者（OWNER） | 全事業部・銀行・予算ルール・契約・顧客・稼働・設定・監査ログ |
| 経理（ACCOUNTING） | 売上・経費・入金・支払・稼働明細・銀行明細・照合・月次締め。予算ルールは閲覧のみ |
| 事業部責任者（MANAGER） | **担当事業部だけ**の顧客・案件・売上・経費・利益・予算・稼働・日報承認・経費承認。銀行残高・他事業部は見えない |
| ドライバー（DRIVER） | 本人の稼働希望・確定スケジュール・日報・経費・公開済み明細・契約のみ |

- 判定はすべてサーバー側（`src/server/access.ts`）。画面・Server Action・ファイル取得・Excel/PDF出力が同じ関数を通る。
- 担当外のデータは「見つかりません」を返し、存在を漏らさない。
- 事業部の絞り込みは SQL の条件として付与（取得後に画面で隠すのではない）。

## 4. データモデル（主要テーブル）

- 認証: `app_user`（メール/パスワード・LINE ID・状態）、`session`（トークンはハッシュのみ保存）、`invitation`（招待トークン・期限・1回限り）、`email_verification`
- 組織: `company_setting`（1行）、`division`、`user_division`（責任者の担当）、`expense_category`
- 取引先: `partner`（法人/個人、`is_customer`・`is_contractor` の両方を持てる）、`partner_contact`、`partner_division`、`partner_note`
- 案件: `project`（事業部・顧客・区分・月額/単発・金額・期間・納期・状態・日報項目設定・外部ID）
- 売上と入金（別管理）: `sale`（計上日・計上月・税区分・請求状況・入金予定日）、`receipt`（入金）、`receipt_allocation`
- 経費と支払（別管理）: `expense`（状態・支払状況・精算方法・明細行への紐付け）、`expense_file`、`payable`（支払予定）、`payment`
- 配賦: `allocation_rule`（固定割合 / 売上比）、`allocation_share`
- 予算: `budget_rule`（対象・期間・固定上限・人数連動・売上/利益連動割合・繰越・適用期間・超過時の扱い・優先順位）、`budget_commitment`（発注済み費用）、`budget_request`（追加申請）、`budget_adjustment`
- 月次: `month_close`（締め状態）、`correction`（締め後の訂正記録）
- 銀行: `bank_account`（マスク番号のみ）、`bank_transaction`（区分: 売上入金/経費支払/明細支払/振替/借入/税金/その他/未分類）、`bank_match`、`bank_sync_run`
- 契約: `contract_template`（版）、`contract`（当事者・条件・状態）、`contract_revision`、`contract_file`
- 稼働: `driver`（資格・車両・エリア・上限）、`availability_period`（対象月・締切）、`availability`（日ごとの可否・時間）、`availability_change_request`、`shift_slot`（案件・日付・時間帯・必要人数・条件）、`assignment`、`assignment_history`
- 日報: `daily_report`、`daily_report_file`、`daily_report_revision`
- 単価と明細: `rate`（日額/時間/件数/固定月額、適用期間）、`statement_adjustment`、`statement`（版・状態・確定時のスナップショット）、`statement_line`、`statement_inquiry`
- 通知: `email_outbox`（`dedupe_key` 一意＝重複送信防止、試行回数、失敗理由）、`reminder_rule`
- AI: `action_card`（ルールキー＋対象キーで一意、根拠数値と期間、状態）
- Clean Up: `integration_setting`、`external_ref`（外部ID ↔ 内部ID、取込元・取込日時）、`import_run`
- 共通: `stored_file`、`audit_log`（追記のみ、DBトリガーで変更・削除禁止）

## 5. 集計ルール

| 指標 | 定義 |
|---|---|
| 売上 | `sale` の税抜金額。計上月で集計。請求・入金とは別 |
| 直接経費 | 事業部に紐付く承認済み経費（税抜）＋確定済み稼働明細の稼働分（外注費） |
| 共通経費 | 事業部なし（全社）の承認済み経費。配賦ルール（固定割合 / 売上比）で各事業部へ按分して表示。全社合計では共通経費を1回だけ数える |
| 配賦後利益 | 売上 − 直接経費 − 配賦額 |
| 未収金 | 計上済み売上（税込）− 入金済み額 |
| 未払い | 支払予定のうち未払いの額 |
| 資金余力 | 銀行残高合計 − 今後30日の支払予定 ＋ 今後30日の入金予定（日数は設定可）。**予算とは別指標** |

### 予算の利用可能額
`利用可能額 = 予算上限 − 計上済み実績（承認済み・支払済み） − 予約額（未計上）`

- 予約額 = 申請中の経費（設定で含める/含めない）＋ 未消化の発注済み費用
- 状態から毎回計算するため、申請中→承認で予約から実績へ移り、二重に引かれない。差戻し・却下・取消で予約から外れる。
- 発注済み費用は、実際の経費を紐付けた時点で「消化済み」となり予約から外れる。
- 予算上限 = 固定上限 ＋ 人数 × 1人あたり額 ＋ 対象売上（または利益）× 割合 ＋ 繰越 ＋ 承認済みの追加額。金額はすべてルールの設定値で、コードに固定しない。
- 同じ対象に複数のルールがある場合は優先順位の高いものを適用し、画面に「適用ルールと計算根拠」を表示。

### 二重計上を防ぐ設計
- 経費は1件1回だけ集計（`expense.status IN (承認, 支払済み)`）。精算方法が「稼働明細に含める」の場合も経費として1回、支払は明細経由で1回。
- 稼働明細は稼働分（外注費）と立替経費の行を分け、立替経費行は元の経費を参照するだけで外注費に加算しない。
- 銀行取引は売上・経費に自動変換しない。照合（入金・支払との紐付け）だけを行い、振替・借入・税金は区分で除外。
- 1ドライバー×1か月の有効な明細は1件（部分一意制約）。再生成は下書きのみ置き換え、確定後は訂正版を作る。

1. 認証・権限・事業部・顧客・案件・売上・経費・予算・月次締め・基本ダッシュボード
