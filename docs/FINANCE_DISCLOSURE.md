# 入出金の管理と公開範囲（サービス提供者・本社・スタッフ）

サービス提供者が入出金を管理し、本社と各スタッフに「何を見せるか」を決める仕組みです。
3つの画面は同じシステムの中の、権限ごとの画面です。

| 画面 | 使う人 | URL | できること |
|---|---|---|---|
| サービス提供者画面 | サービス提供者（役割 `PROVIDER`） | `/p` | 担当会社の銀行CSV取込・デモ同期、原本の確認、手動取引の登録と訂正、分類・メモ・確認状態の編集、集計対象外の設定、本社・スタッフへの公開設定（一括を含む）、公開権限の設定、見え方の確認、操作履歴 |
| 管理画面（本社） | 経営者・経理 | `/app/bank`（入出金・公開分）、ダッシュボードの「資金」 | 公開された入出金の閲覧。許可された残高・集計・CSV出力 |
| スタッフ画面 | ドライバー | `/d/finance`（「その他」に公開分があるときだけ表示） | 本人または所属事業部あてに公開された入出金だけ |

事業部責任者は、今までどおり入出金を見られません。振込・送金の機能はありません。

## 担当会社と提供者アカウント

- 提供者が扱えるのは、運営側で割り当てた会社（`provider_assignment`）だけです。担当外の会社は、一覧・URL直打ち・API・CSV出力のどれでも「見つかりません」になります
- 提供者アカウントの作成・担当の追加と解除は、運営側のコマンドだけで行います（本社・スタッフの画面からは操作できません）

```bash
PROVIDER_EMAIL=… PROVIDER_NAME=… PROVIDER_PASSWORD='…' pnpm provider create
PROVIDER_EMAIL=… pnpm provider assign                 # 自社を担当にする（COMPANY_ID で別の会社）
PROVIDER_EMAIL=… COMPANY_ID=… pnpm provider unassign  # 担当を外す（次の操作からすぐ反映）
COMPANY_NAME=… pnpm provider add-company
pnpm provider list
```

- 本社・スタッフは「自社」（`company.is_self`）に属します。売上・支払予定との照合は自社の口座だけで行えます

## 入出金ごとの公開設定

| 項目 | 値 | 初期値 |
|---|---|---|
| 公開状態 | 下書き／公開中／公開停止 | 下書き（取込・同期・手動登録のすべて） |
| 本社に公開 | する／しない | しない |
| スタッフに公開 | する／しない | しない |
| スタッフへの公開対象 | 指定スタッフ・事業部（複数可） | なし |

- 本社に見えるのは「公開中」かつ「本社に公開する」の取引だけです
- スタッフに見えるのは「公開中」かつ「スタッフに公開する」かつ「公開対象に本人または所属事業部が含まれる」取引だけで、さらに提供者がそのスタッフに「明細の閲覧」を許可している場合だけです（初期状態では、どのスタッフにも何も表示されません。本社や事業部責任者がドライバーを招待しても、その人の閲覧範囲は提供者が許可するまで広がりません）
- 本社に公開してもスタッフには公開されません（逆も同じ）。設定は継承しません
- スタッフに公開する取引には、公開対象を1つ以上選ぶ必要があります

**一括操作**（「入出金と公開状況」画面の下）: 取引を選ぶか、絞り込み条件（期間・口座・分類・案件・公開状態など）に当てはまる取引すべてを対象にして、「対象件数と公開先を確認」→ 件数と、変更後に本社・スタッフに表示される件数を確認 →「◯件を変更する」で実行します。確認したあとで対象が変わった場合は実行しません。

公開の操作は、取引ごとに実行者・日時・対象・変更前後の設定（公開状態・本社・スタッフ・公開対象）を操作履歴に残します。

## 「入出金の操作」の4つの種類

| 操作 | 画面 | 記録 |
|---|---|---|
| 1. 表示先を変更する | 一覧（一括）・取引の詳細 | `bank.visibility` |
| 2. 分類・メモ・確認状態・案件を編集する | 取引の詳細 | `bank.meta`（メモは提供者だけが見る） |
| 3. 手動取引を登録・訂正する | 口座・取込・手動登録／取引の詳細 | `bank.manual_create`・`bank.correction`（理由必須） |
| 4. 重複や誤取込を集計対象から除外する | 取引の詳細 | `bank.exclude`・`bank.include`（理由必須） |

- **原本は変更・削除できません**（データベースのトリガーで拒否）。銀行から取得した日付・金額・内容・残高は残り、訂正は `bank_txn_correction` に追記します。表示・集計には最新の訂正後の値を使い、詳細画面に原本と訂正履歴を並べて表示します。訂正の記録も変更・削除できません
- **「非公開」と「集計対象外」は別の設定です。** 非公開にしても、原本や全取引の集計からは消えません。集計対象外にした取引は一覧に「集計対象外」と表示されたまま、どの合計にも含まれなくなります

## 残高・集計の公開権限

公開した明細とは別に、次を本社・スタッフ（一人ずつ）ごとに許可します（「公開権限」画面）。

| 権限 | 本社の初期値 | スタッフの初期値 |
|---|---|---|
| 明細の閲覧（公開した取引） | 許可 | **不可**（提供者が一人ずつ許可） |
| 公開された取引だけの集計 | 許可 | 不可 |
| 全取引の集計（非公開を含む） | 不可 | 不可 |
| 実際の銀行残高 | 不可 | 不可 |
| CSV出力（閲覧できる明細だけ） | 不可 | 不可 |

- 本社・スタッフの集計は、初期状態では閲覧できる取引だけで計算し、「公開対象の入出金合計」と表示します（実際の残高や会社全体の収支ではないことを画面に明記）
- 全取引の集計や実際の残高を公開すると、公開した明細との差から非公開の取引の金額が推測できる場合があります。設定画面にその説明を表示しています
- ダッシュボードの「資金余力」とAIの資金カードは、本社に「実際の銀行残高」が許可されている場合だけ計算・表示します

## サーバー側での強制

- 判定は `src/server/finance-visibility.ts` の1か所（`visibleCond`）に集めています。一覧・詳細・検索・集計・残高・月別推移・件数・CSV出力・プレビューはすべてここを通り、許可されていない取引や値はSQLの段階で除外します（ブラウザに送ってから隠すことはしません）
- 毎回データベースで判定するので、公開停止・担当解除はその場で反映されます。出力用のファイルやダウンロードURLは保存せず、出力のたびに権限を確認して作ります
- **出力済みのCSVは回収できません。** 公開を止めても、すでにダウンロードされたファイルは利用者の手元に残ります（画面にも表示）
- 通知: AIの対応カード・Slackの毎日の要約に、取引の内容は含めません（銀行同期の失敗・未照合は提供者画面に表示）。資金のカード（残高を含む）は、本社に実際の残高が許可されている間だけ、過去のものも含めて表示します。
- 提供者の照合で作られる入金記録・支払済みの記録（本社にも見える）には、取引の内容を書きません。本社の監査ログには「サービス提供者が銀行照合」とだけ残します。本社の監査ログ画面には入出金・公開設定・出力の履歴を表示しません（提供者の「操作履歴」で確認）
- 取引には添付ファイルはありません（今後追加する場合も同じ判定を通すこと）
- 提供者は本社・スタッフの画面と処理に入れません（ログイン後は `/p`。本社用の Server Action・API は拒否）。本社・スタッフは提供者の画面と処理に入れません
- 本社の利用者は提供者アカウントの変更・作成ができず、公開設定・公開権限も変更できません

## 見え方の確認（プレビュー）

「見え方の確認」で、本社または特定のスタッフとして表示される明細・残高・集計と、表示されない項目を確認できます。実際の閲覧と同じ関数（`previewViewer` → `listVisibleTxns`・`summarize`）を使っています。

## 移行時の扱い

この機能を入れる前からある取引は、すべて「下書き（非公開）」になります。本社に見せる取引は、提供者が公開してください。
