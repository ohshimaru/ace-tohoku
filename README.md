# 経営ナビ（株式会社エースナンバー東北 経営管理システム）

経営・経理・事業部・業務委託を1つで管理する Web システムです。数値の集計と異常の検知はアプリのルールで行い、
「次に何をすべきか」を根拠の数値つきの行動カードで示します（AIの文章整形は任意。なくても動きます）。

- 会社側（PC）: `/app` … 経営者・会社管理者 / 経理 / 事業部責任者
- ドライバー側（スマホ）: `/d` … 業務委託ドライバー（LINEでログイン）

設計: [docs/DESIGN.md](docs/DESIGN.md)／運用・公開手順: [docs/OPERATIONS.md](docs/OPERATIONS.md)／実装状況: [docs/STATUS.md](docs/STATUS.md)

## ローカルで起動する

必要なもの: Node.js 22 以上、pnpm 10、PostgreSQL 16

```bash
pnpm install
cp .env.example .env          # DATABASE_URL・APP_SECRET・CRON_SECRET を設定。開発では DEMO_LOGIN=true
pnpm db:migrate               # テーブル作成（DB制約・トリガー含む）
pnpm db:seed                  # 初期データ（事業部3つ・費目・契約書ひな形）。何度実行しても重複しない
pnpm db:seed-demo             # 任意: 架空のデモデータ（デモ用アカウントはパスワードなし・デモログイン専用）
ADMIN_EMAIL=you@example.com ADMIN_NAME="代表 太郎" ADMIN_PASSWORD='12文字以上の強いパスワード' pnpm admin:create
pnpm dev                      # http://localhost:3000
```

## デモの操作手順（デモデータ投入後）

1. `/login` の「デモログイン」から **代表 太郎（デモ）** を選ぶ → ダッシュボードで売上・利益・資金・行動カードを確認
2. 「対応すること」で行動カード（根拠の数値・期間・推奨・担当・期限・状態）を確認し、状態を「対応中」「完了」に変更
3. 「損益・予実」で事業部別損益（共通経費は配賦しても全社で1回だけ）と案件別、数値クリックで明細へ
4. **委託 責任者（デモ）** でログイン → 「稼働スケジュール」で翌月の提出状況・枠作成・自動割当（下書き）→ 確定
5. ドライバー画面 `/d/login` のデモログインで **高橋 三郎（デモ）** → 翌月の稼働希望をまとめて入力して提出 → 日報を書く
6. 責任者で「日報」を承認 → 経理 花子（デモ）で「稼働明細」を作成・確定・公開 → ドライバー側で確認・PDF/Excel
7. 「ドライバー」で招待リンクを作成 → 別のブラウザで開き「模擬LINEで連携」→ 責任者が承認 → ログイン可能に
8. 「提供者 一郎」で入出金を取込・照合し、本社・スタッフへの公開を設定 → 経理・ドライバーで見え方を確認
9. 「Clean Up連携」で Clean Up の請求書CSVを取込（請求書番号で重複なし）
10. 「契約書」でひな形テンプレートから契約書を作成 → 社内確認 → 送付 → 締結済みファイルの保存 → 締結

pnpm build && pnpm test:e2e   # 本番ビルドを起動して画面操作（E2E_DATABASE_URL）
